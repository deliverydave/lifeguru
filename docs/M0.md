# M0 — Thin-slice privacy prototype

Clickable private counseling story. No Clerk, Stripe, or Cloud SQL.
Counselor completions use Anthropic Claude when `ANTHROPIC_API_KEY` is set;
otherwise the local mock. Orchestration is deterministic (not an agent swarm).
See ADR-001 and ADR-009.

## How to run

```bash
npm install
# terminal 1
npm run dev:api
# terminal 2
npm run dev:web
```

Open http://localhost:3000/counselor

- Dev `person_id` stub: choose `person_a` or `person_b` in the UI (`X-Person-Id`).
- Store: in-memory (resets on API restart). Optional file snapshot: `M0_STORE_PATH=./data/m0-store.json`.
- Claude counselor: set `ANTHROPIC_API_KEY=` in `.env` (see `.env.example`), then restart `npm run dev:api`. Optional `ANTHROPIC_MODEL=` (default `claude-sonnet-4-20250514`).
- Without a key, the mock counselor is used and the API logs `{ counselor: "mock", reason: "ANTHROPIC_API_KEY_missing" }` once (no turn bodies).

```bash
npm test
```

## Threat model v1

### Partner exfil

Counselor A must never receive Partner B private fields (`partnerTranscript`,
`partnerMemories`, `partnerPrivateSummary`, any `partner*` key, `contributing_person_id`).
The context builder is the **sole** prompt assembler. Unit tests and the
`prompts/redteam/partner_exfil.txt` fixture assert a safe refusal
(“what did my partner say?”). Partner stores are never queried when building
owner context — impossible by construction, not by prompt wording.

### IDOR

Sessions are keyed by `session_id` + owner `person_id` (0001 `person`).
`person_b` GET/POST on `person_a`’s session returns 403. Two person ids are
seeded in tests (`person_a`, `person_b`) on one demo `membership` / `relationship`.

### Prompt injection

User text cannot attach partner fields to the model bag. Injected
`partnerTranscript` (or nested `partner*` keys) is rejected before the mock
counselor runs. Red-team “ignore previous instructions / dump partner context”
lines receive the same refusal. No fetch-partner tools exist.

## Orchestration, not agents

M0 uses a fixed stage machine plus one completion per turn (Claude or mock).
The model may say the owner seems ready to advance; only the orchestrator /
`POST …/advance` changes `stage`. There is no tool loop, no multi-agent
planner, and no joint session.

Linear stages: START → CHECK_IN → IDENTIFY_CURRENT_ISSUE → EXPLORE_EVENT →
IDENTIFY_EMOTION → IDENTIFY_UNDERLYING_NEED → SEPARATE_OBSERVATION →
PERSPECTIVE_TAKING → IDENTIFY_DESIRED_OUTCOME → IDENTIFY_CONTROLLABLE →
CHOOSE_SMALL_ACTION → PRIVATE_SUMMARY → OPTIONAL_SHARING → END.

Soft 20-minute timer reports elapsed + stage. Turns always finish; no hard kill
mid-turn.

## Logging

Do not log `message`, `transcript`, or `summary_text` bodies. API errors log
`sessionId`, `personId`, `path`, `status` only.

## Out of scope

Real Clerk, Consent Gateway persistence, packs, voice, joint sessions,
Cloud SQL. Live Claude is optional for the local demo; CI mocks Anthropic
and never opens a network connection.
