# M1 — Auth + relationship linking

Two humans can sign up, accept privacy + coaching-not-therapy disclaimers, create or join a relationship via a one-time invite, and each only see their own private counselor data.

Clerk is the IdP (ADR-003). The counseling domain uses an opaque `person_id` from `identity_person_map` / AccountPersonMap — never a client-supplied id on the live path.

## Acceptance

- Sign up / sign in via Clerk (or documented test bypass).
- Onboarding records timestamp + version for `privacy-explainer-v1` and `coaching-not-therapy-v1`.
- Create relationship → generate invite link → second human accepts once.
- Invite reuse and expiry fail closed (409 / 410).
- My Counselor only after auth + disclaimers + active membership.
- Relationship banner shows your relationship id and member count — not partner transcripts.
- User A GET/POST of User B’s session returns 403.
- List/me/relationship payloads never include the other person’s private rows.
- Coaching-not-therapy copy stays visible; default share remains Keep private.
- Claude counselor still allowlisted as in M0 (no partner fields in the prompt).
- Stripe stays a stub (`BILLING_ENABLED` off).

## How to run (see also README “M1 demo”)

```bash
npm install
cp .env.example .env
# set Clerk keys (required for live auth)
npm run dev:api
npm run dev:web
```

Open http://localhost:3000 — sign in, onboard, create/join, then My Counselor.

Without Clerk keys, `/v1/*` returns **503** unless `M1_DEV_AUTH_BYPASS=1` (API) and `NEXT_PUBLIC_DEV_AUTH_BYPASS=1` (web). Bypass is for tests / local click-through only.

## Threat notes

### Authz / IDOR

- Production `person_id` is derived only from a verified Clerk `sub` via AccountPersonMap (webhook `user.created` or first authenticated request).
- `X-Person-Id` is ignored when Clerk is configured. Tests may set `M1_DEV_AUTH_BYPASS=1` to send that header.
- Sessions are owner-scoped (`session.personId === auth.person_id()`). Same-relationship partners still get 403 on each other’s sessions.
- Relationship and invite routes require a membership row (`repo-filters.mjs` / `0003` RLS sketches).
- Invited (not active) membership cannot open a counselor session.

### Invites

- Raw token is shown once; store keeps SHA-256 `token_hash` only.
- One-time: `used_at` + status `accepted` → reuse 409.
- Expiry: status `expired` → 410. Fail closed if missing/revoked.
- Creator cannot accept their own invite. Max two active members.

### Partner exfil

Unchanged from M0: context builder is the sole assembler; partner-private keys never enter the counselor bag. Do not log `message` / `transcript` / `summary_text`.

### Webhook

`POST /v1/webhooks/clerk` is unauthenticated except Svix signature (`CLERK_WEBHOOK_SECRET`). Invalid signatures 401. Provisioning also happens on first JWT so local demo does not need a public webhook URL.
